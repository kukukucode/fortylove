# Fortylove 改善要件書

## 1. 文書概要

### 1.1 目的
本要件書は、Fortylove の新歓管理・FAQ・Chatbot・管理画面・一般画面について、使いやすさ、運用性、回答精度、視認性を改善するための要件を整理したものとする。

### 1.2 対象
- Chatbot
- Markdown知識取り込み
- FAQ
- 管理画面
- 一般ユーザー向け画面
- 新歓受付画面
- ローディング・画面遷移
- UI・アニメーション

### 1.3 対象外
- 管理者向けMarkdown本文そのものの再編集
- 新歓生向けMarkdown本文そのものの再編集
- Q&A本文の口調調整や細分化

これらは別作業として扱う。

---

# 2. Chatbot 要件

## 2.1 回答フロー

Chatbot は以下の順番で回答する。

```text
質問
↓
イベント系？
├─ YES → events DB から該当イベントを検索して回答
└─ NO
    ↓
キーワード + Embedding で知識検索
    ↓
高一致 → 該当知識の回答を返す
中一致 → 関連知識を最大3件取得し、Geminiで自然な1回答にまとめる
一致なし → 資料には記載がありません と表示
           + 一般的な回答を見る ボタン
              ↓
           ユーザーが押した場合のみ Gemini で一般回答
```

### 2.1.1 イベント系
- 新歓イベントの日程、場所など変動する情報は Markdown より events DB を優先する。
- 固定知識に古い日程を残さない。

### 2.1.2 高一致
- 関連性が十分高い場合は、該当知識の回答をそのまま返す。
- 不要な要約や再生成は行わない。

### 2.1.3 中一致
- 関連知識を最大3件まで取得する。
- 質問と関連知識を Gemini に渡し、自然な1回答へまとめる。
- 複数カードにまたがる質問にも対応する。

### 2.1.4 一致なし
- Gemini を自動実行しない。
- まず資料に記載がないことを表示する。
- 一般的な回答を見るボタンを表示する。
- ボタン押下時のみ一般回答を生成する。
- 一般回答は Fortylove の公式回答ではないことを明示する。

---

## 2.2 検索精度

- キーワード検索と Embedding を併用する。
- タイトル内の単語1つだけで過剰に高スコアになる誤一致を減らす。
- 明示キーワードは、実際に利用者が入力しそうな自然な表現を優先する。
- 高一致、中一致、一致なしの閾値を明確に設定する。
- 類似候補が複数ある場合は、必要に応じて複数件を利用して回答する。

---

## 2.3 Chatbot 表示方針

一般ユーザーには内部処理を表示しない。

### 表示しないもの
- Embedding
- Markdown検索
- Gemini
- DB検索
- 内部スコア
- 根拠
- 参照元
- 参照章
- 参照ファイル名
- 技術構成
- 内部処理説明

技術名を含む常時表示は削除し、初回案内または「利用について」に以下の短い説明を置く。

```text
回答のため外部AIサービスを利用する場合があります。個人情報は入力しないでください。
```

### 回答文体
- AIっぽい定型表現を避ける。
- 不要な日本語のかぎかっこを多用しない。
- 管理者向けは、先輩が後輩へ教えるような柔らかい口調。
- 新歓生向けは、丁寧で親しみやすい口調。
- 必要以上に長くしない。

---

## 2.4 Chatbot モーダル

- × ボタンで閉じられる。
- モーダル外の背景をクリック・タップしても閉じられる。
- モーダル内部を操作した場合は閉じない。
- スクロール中の誤操作で閉じない。
- PC、スマホ両方で利用できる。

---

## 2.5 Chatbot 有効・無効切り替え

Super Admin 用の Chatbot ON/OFF は iPhone の設定画面のようなトグルスイッチUIにする。

要件：
- 現在の状態が一目で分かる。
- ON/OFF 操作が直感的。
- 通常のボタンやチェックボックスより視認性を優先する。

---

# 3. Markdown 知識取り込み要件

## 3.1 1ファイルあたりの上限

- 現在の100件上限を1000件へ変更する。
- 1000件を超えた場合、サイレントに切り捨てない。
- `.slice(0, 1000)` のような実装は禁止する。
- 上限超過時はそのファイルの取り込みを中止する。

### エラー表示例

```text
1000件の上限を超えています
このファイルには 1,124 件のデータがあります
```

### 成功時表示例

```text
管理者向けDB4CB_完成版.md
332件を取り込みました
```

---

## 3.2 複数Markdownの一括取り込み

- `.md` ファイルを一度に複数選択可能にする。
- ドラッグ&ドロップでも複数追加可能にする。
- 各ファイルを個別に解析・取り込みする。

### 状態表示
各ファイルに以下の状態を表示する。

- 読み込み待ち
- 解析中
- アップロード中
- 完了
- エラー

1ファイルが失敗しても、他ファイルの成功・失敗が分かるようにする。

---

## 3.3 現在読み込まれている知識一覧

管理画面で、現在 Chatbot が知識として利用している Markdown を確認できるようにする。

各ファイルで表示する項目：
- ファイル名
- 取り込み済みQ&A件数
- 最終更新日時
- 状態

表示例：

```text
現在読み込み中

✓ 管理者向けDB4CB_完成版.md
  332件
  最終更新 2026/09/06

✓ 新歓生向けDB4CB_完成版.md
  135件
  最終更新 2026/09/06
```

目的：
- 現在何を Chatbot が知識として持っているか分からない状態をなくす。

---

## 3.4 アップロード前確認

ファイル選択後、実際の取り込み前に選択内容を一覧表示する。

表示内容：
- 選択中のファイル名
- ファイル数
- ファイルごとの解析件数
- 合計件数
- 上限超過の有無

表示例：

```text
今回アップロードするファイル

管理者向けDB4CB_完成版.md
332件

新歓生向けDB4CB_完成版.md
135件

2ファイル / 合計467件

[ アップロード ]
```

# 4. FAQ 要件

## 4.1 FAQ を Chatbot 知識として利用

- 管理画面のFAQを Chatbot の知識ソースとして直接利用できるようにする。
- FAQとMarkdownへの二重登録をできるだけなくす。
- FAQ更新内容を Chatbot 側でも利用できるようにする。
- FAQとMarkdownの重複による不自然な回答や検索結果を減らす。

---

## 4.2 一般画面へのFAQ表示

- 一般ユーザー向け画面でFAQが表示されない問題を修正する。
- 新歓生・一般ユーザーがFAQを閲覧できるようにする。
- FAQが管理画面だけに存在する状態にしない。

---

## 4.3 FAQ の展開・折りたたみ

admin 以上のFAQ管理画面では、各FAQを折りたたみ可能にする。

通常時例：

```text
▶ 初心者でも入れますか？
▶ 会費はいくらですか？
▶ 一人でも参加できますか？
```

タップすると回答・編集項目を展開する。

目的：
- 長い回答が常時表示される状態をなくす。
- FAQ一覧全体を見やすくする。

---

## 4.4 FAQ 並び替え

### 操作
- FAQを長押しする。
- そのまま上下へドラッグして並び替える。
- スマホのタッチ操作を優先する。
- PCでもドラッグ操作可能にする。

### 保存方式
- 並び替えるたびにDBへ保存しない。
- 画面上では仮状態として保持する。
- 変更を確定ボタンで一括保存する。

### 視覚フィードバック
- 持ち上げ中のFAQを分かりやすくする。
- 移動先を分かりやすくする。
- 通常スクロールとの誤操作を防ぐ。

---

## 4.5 FAQ 横スワイプ削除

スマホでは iPhone のリスト操作に近い挙動にする。

```text
FAQを横スワイプ
↓
削除ボタンを表示
↓
削除ボタンをタップ
↓
確認
↓
削除
```

要件：
- スワイプだけでは削除しない。
- 削除ボタン押下後も確認を入れる。
- 確認後のみ実削除する。

### ジェスチャー競合防止
- 長押し + 縦移動 → 並び替え
- 横移動 → 削除操作
- 通常の縦移動 → ページスクロール

---

# 5. 新歓受付停止画面

## 5.1 表示条件

新歓受付が停止中の場合、新規登録フォームを終了画面へ切り替える。既存会員のログイン・予約・キャンセル・資料閲覧は継続する。

## 5.2 表示内容

画面中央に、受付終了を分かりやすく表示する。

推奨文言：

```text
今年度の新歓は終了しました！
たくさんのご参加ありがとうございました！
```

## 5.3 UI要件

- メッセージは画面中央に配置する。
- 十分な余白を取り、終了画面として分かりやすくする。
- 新規登録フォームは非表示にし、サーバー側でも登録を拒否する。既存会員の予約フォームは変更しない。
- スマホでも見やすくする。
- 過度に派手にせず、感謝が伝わる明るい画面にする。

---

# 6. ローディング・処理中表示

サイト全体で、処理中か停止中か分からない状態を減らす。

対象：
- 初回ロード
- ページ遷移
- データ取得
- 保存
- Markdown取り込み
- FAQ更新
- Chatbot処理

必要に応じて以下を利用する。
- ローディング表示
- スケルトン
- スピナー
- 進行中表示
- ボタンの処理中状態

---

# 7. アニメーション

JavaScript / CSS 等を利用し、操作状態が分かりやすくなる程度の自然なモーションを追加する。

対象例：
- ページ遷移
- モーダル表示
- FAQ展開・折りたたみ
- トグル
- ドラッグ
- スワイプ
- ボタン
- カード表示

方針：
- 派手さより操作性を優先する。
- 操作の結果や状態変化が分かりやすくなるアニメーションを使う。

---

# 8. UIデザイン改善

サイト全体を現在より洗練された見た目にする。

方向性：
- スマホで使いやすい
- 余白を整える
- 情報の優先順位を分かりやすくする
- カード・モーダル・一覧の統一感を出す
- 管理画面も一般画面も古い業務システム感を減らす
- 必要な場所に自然なアニメーションを入れる
- 見た目のために操作性を落とさない

---

# 9. 権限・操作対象

既存権限構成を前提とする。

- super_admin
- admin
- member

主な管理操作：
- Chatbot ON/OFF → Super Admin
- FAQ編集・並び替え・削除 → admin 以上
- Markdown知識管理 → 現行権限設計を維持しつつ、管理者向けUIで提供

---

# 10. 実装上の共通要件

- 既存機能を壊さない。
- PCだけでなくスマホを優先して確認する。
- FAQのドラッグ・スワイプ・スクロールを競合させない。
- Markdown取り込みエラーを隠さない。
- 大量ファイル・大量Q&Aでサイレント切り捨てをしない。
- 一般ユーザーへ内部技術構成を見せない。
- 管理者には現在のChatbot知識状態を明確に見せる。
- 変動する新歓イベント情報は events DB を優先する。
- UI変更後も既存の認証・権限制御を維持する。

---

# 11. 受け入れ確認項目

実装完了時は最低限以下を確認する。

- Chatbotがイベント系質問をDB優先で回答できる。
- 高一致・中一致・一致なしの3段階が正しく動く。
- 一致なし時にGeminiが自動実行されない。
- 一般的な回答を見るボタンが機能する。
- 1000件以下のMarkdownを取り込める。
- 1000件超過時に切り捨てずエラーになる。
- 複数Markdownを一括選択・取り込みできる。
- 現在読み込み中の知識一覧が確認できる。
- アップロード前に対象ファイル・件数を確認できる。
- FAQが一般画面に表示される。
- FAQを展開・折りたたみできる。
- FAQを長押し・縦ドラッグで並び替えできる。
- FAQ並び替えが変更を確定するまでDBへ保存されない。
- FAQを横スワイプして削除操作を出せる。
- 削除は確認後のみ実行される。
- Chatbotモーダルを背景タップでも閉じられる。
- Chatbot ON/OFF がトグルUIになっている。
- 新歓受付停止時に中央へ終了メッセージが表示される。
- 新歓受付停止時に新規登録できず、既存会員は予約・キャンセルできる。
- ローディング・保存中・取り込み中の状態が分かる。
- スマホで主要操作が問題なく行える。

# 12. 確定補足（2026-09-06）

- 会話を消す機能は追加しない。ウィジェットを閉じても会話を保持する。送信済みの文章を入力欄に残さず、ブラウザの入力履歴候補を抑制する。
- super_adminの管理画面に右下ウィジェットを常設する。公開停止中も利用可能で、管理者・一般ユーザーの参照元を切り替えてテストできる。
- 一般回答は一般的なテニス・学生生活の対象質問だけに限定する。Fortylove固有の費用、条件、日程、個人情報、運営判断を推測しない。
- 一般回答ボタンの実行も1日の利用回数に含める。super_adminは上限対象外。
- 公開済みFAQだけを一般画面・Chatbotの回答元に含める。FAQとMarkdownの回答重複を抑える。
- Markdownは一括10ファイル・合計1MB（1,000,000バイト）まで。UTF-8、1ファイル最大1,000件とし、失敗したファイルの旧データは維持する。
- ファイル単位で検証・Embedding生成・保存を実行する。保存はDBトランザクションで差し替える。処理状況と再試行を提供する。
- 既存のMarkdownは再取り込み、既存FAQは検索データ更新でEmbeddingを作成する。検索API障害時はキーワード検索を継続する。
- ドラッグの持ち手と上下ボタンを併用する。横スワイプは削除ボタンを出すだけとし、確認前に削除しない。
- 端末の「動きを減らす」設定に対応する。
- GitHubへのプッシュと本番反映は後続作業として保留する。
